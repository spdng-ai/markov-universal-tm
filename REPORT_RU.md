# Универсальный симулятор машины Тьюринга одним нормальным алгоритмом Маркова

Учебный проект. Полная конструкция, исполнение, проверка и доказательство.

## 1. Точная постановка

Строится **один фиксированный нормальный алгоритм Маркова A**. Его вход — конечное слово, содержащее программу детерминированной машины Тьюринга M и её начальную конфигурацию на двоичном слове w. Таблица правил A не зависит от M и w.

Результат конструкции: **800 упорядоченных буквальных правил над алфавитом из 88 букв**. Одна замена заключительная. Все остальные обычные. Полная таблица находится в `rules.json`, читаемая запись всех 800 правил — в `rules_readable.txt`, полный фиксированный генератор — в `fixed_rules.py` и приложении A этого отчёта.

### 1.1. Модель входной машины

- Лента бесконечна в обе стороны; её ячейки можно нумеровать целыми числами.
- Ленточный алфавит Γ = {0, 1, _}. Символ `_` обозначает пустую ячейку.
- Входной алфавит {0, 1}; пустое входное слово допустимо.
- Множество состояний Q — любое конечное подмножество положительных целых чисел. Верхней общей границы на номера и число состояний нет.
- Начальное состояние q₀ задаётся во входе.
- Частичная функция переходов имеет тип δ: Q × Γ ⇀ Q × Γ × {L, R, S}.
- Команда δ(q,a) = (p,b,D) означает: записать b, передвинуть головку согласно D и перейти в p. S означает отсутствие движения.
- **Машина останавливается тогда и только тогда, когда для текущей пары (q,a) переход не определён.** Отдельные принимающие/отвергающие состояния здесь не нужны. Обычное выделенное состояние остановки представляется состоянием без исходящих команд.

Первоначально головка находится в ячейке 0, вход записан с неё вправо, остальные ячейки пусты. При пустом входе в ячейке 0 также `_`.

### 1.2. Почему этого класса достаточно

Ограничение ленточного алфавита до двух рабочих символов и пустого не уничтожает универсальность. Конструктивное объяснение: символы любого конечного алфавита можно представлять блоками одной фиксированной для данной машины длины k. Непустые символы кодируются различными двоичными блоками, пустой — блоком из k пустых ячеек. Головка симулирующей машины в начале каждого моделируемого шага стоит в начале блока.

Её конечное управление прочитывает k ячеек, запоминает один из конечного числа кодов, записывает нужный блок, возвращается к его началу и сдвигается на k ячеек в нужную сторону. Все промежуточные позиции и прочитанные коды помещаются в конечное число состояний, поскольку k фиксировано для этой машины. За пределами записанного участка уже находятся пустые блоки. При необходимости вход заранее переводится в блочную кодировку. Таким образом моделируется любая детерминированная одноленточная машина с конечным алфавитом.

Это обоснование выбора класса входных машин, а не замена построения A. Сам A ниже строится явно. Стандартное утверждение о двоичном алфавите также приведено в курсе École Polytechnique, §1.6, proposition 21; ссылка в конце отчёта.

## 2. Кодировка

### 2.1. Состояния и команды

Состояние с номером q ≥ 1 кодируется словом u^q: q повторений **одной и той же буквы `u`**. Например, состояния 1, 2, 5 имеют коды `u`, `uu`, `uuuuu`.

Команда δ(q,a) = (p,b,D) кодируется так:

```text
; u^q a u^p b D
```

Пробелы здесь нужны только для пояснения, во входе их нет. Например:

```text
;uu0uuu1R
```

означает δ(2,0) = (3,1,R). Разделители между полями не нужны: `u` не принадлежит Γ, а L/R/S не принадлежат ни Γ, ни {u}.

Программа P — конкатенация таких записей в любом фиксированном порядке. Пустая программа P = ε разрешена. Список всех состояний отдельно не нужен: достаточно начального состояния и команд. Требуется не более одной команды для каждой пары (q,a).

Программа инверсии:

```text
;u0u1R;u1u0R
```

### 2.2. Стабильное представление конфигурации

В моменты между моделируемыми переходами слово имеет вид:

```text
⟨READY⟩ ^ P # u^q [ L @ a R ]
```

Здесь P, q, L, a, R — **метапеременные только в объяснении формата**, не части правил. L и R обозначают конечные слова над Γ слева и справа от головки. В реальном слове нет пробелов, степеней или этих метапеременных.

`@` стоит непосредственно перед ячейкой под головкой. Слева от `[` и справа от `]` подразумевается бесконечное продолжение из `_`. Представленный участок всегда содержит хотя бы одну ячейку. При выходе головки за его край дописывается одна пустая ячейка; участок никогда не сокращается.

Например:

```text
⟨READY⟩^;u0u1R;u1u0R#u[@01011]
```

Это полное начальное слово для инверсии `01011`.

**Важно про координаты.** Слово хранит положение головки относительно представленного участка, а не абсолютный номер его левого края. Переходы Тьюринга не используют абсолютные координаты, поэтому общий сдвиг нумерации не влияет на вычисление. Формально слово представляет конфигурацию (q,T,h), если для некоторого целого ℓ выполнены h = ℓ + |L|, T[ℓ..ℓ+|LaR|−1] = LaR и вне этого интервала лента пуста. При расширении слева ℓ уменьшается на 1. В доказательстве ℓ — математический параметр, а не скрытая переменная Python.

Независимый проверяющий симулятор действительно хранит целочисленные координаты, левую и правую границы. При сравнении он выдаёт весь тот же участок и позицию головки в нём. Проверка не ограничивается совпадением непустых символов.

### 2.3. Начальный вход и результат

Для непустого w = aR кодировщик выдаёт:

```text
⟨READY⟩^P#u^q₀[@aR]
```

Для пустого w:

```text
⟨READY⟩^P#u^q₀[@_]
```

После остановки получается:

```text
!^P#u^q[L@aR]
```

Это **полный результат**, включающий программу, конечное состояние, участок ленты и головку. `!` — обычная буква результата; остановку вызывает пометка заключительности у последнего правила. Для удобства CLI дополнительно показывает содержимое участка без внешних `_`. Это только отображение результата; внутренние пустые ячейки сохраняются. Для произвольной машины такое отображение не обязано быть двоичным числом.

### 2.4. Фиксированный алфавит

| Часть | Буквы | Число |
|---|---|---:|
| Данные и разделители | `^ ; # u 0 1 _ L R S [ @ ] x v y : !` | 18 |
| Управление | Unicode U+E000, …, U+E045 | 70 |
| Всего | Объединение непересекающихся наборов | 88 |

Каждое обозначение `⟨READY⟩`, `⟨CMP_0⟩` и т. п. — имя **одной конкретной буквы**, а не строка из букв имени и не переменная. Например, READY = U+E000, CMP_0 = U+E005. Таблица соответствий полностью записана в `controls.json`.

В `rules.json` эти буквы записаны стандартными JSON-экранированиями: `"\ue000^"` при чтении JSON превращается в строку из двух символов: U+E000 и `^`. Никаких регулярных выражений или шаблонов интерпретатор не использует.

Рабочие пометки:

| Буква | Значение |
|---|---|
| `:` | начало единственной рассматриваемой команды, временно вместо `;` |
| `x` | уже сопоставленная буква `u` в исходном состоянии команды |
| `v` | уже сопоставленная буква `u` в текущем состоянии |
| `y` | уже скопированная буква `u` в целевом состоянии команды |

### 2.5. Предусловия

Вход должен иметь указанный формат, положительные коды состояний, символы из Γ, направления L/R/S, единственную головку, непустую представляемую ленту и детерминированную программу. Во входе отсутствуют рабочие пометки x/v/y/:/!, а из управляющих букв присутствует ровно READY в начале.

`codec.py` проверяет исходную JSON-машину и двоичность входа. Сам A не обязан распознавать испорченные кодировки. За пределами предусловий его поведение не специфицировано; естественная остановка из-за отсутствия применимого правила там возможна.

## 3. Архитектура одного перехода

Внутри слова находится **ровно одна управляющая буква**. Удобно мысленно считать её курсором. Она не является дополнительным механизмом: «движение курсора» — обычная замена соседних символов.

Например, эти две конкретные замены действительно входят в таблицу:

```text
⟨TO_HEAD⟩0 → 0⟨TO_HEAD⟩
0⟨REWIND_0⟩ → ⟨REWIND_0⟩0
```

Первая передвигает управляющую букву на одну позицию вправо, вторая — влево. Сам символ ленты `0` при этом не изменяется. Аналогичные необходимые буквальные замены для остальных символов уже развёрнуты в файле правил.

| Этап | Действие правилами | Что сохраняется |
|---|---|---|
| Чтение | дойти до `@`, запомнить 0/1/_ выбором одной из трёх управляющих ветвей | лента и программа |
| Выбор | вернуться к `^`, выбрать следующую запись, заменить её `;` на `:` | порядок записей |
| Сравнение | помечать пары `u` как x и v, проверить одновременное окончание кодов и прочитанный символ | исходные длины восстанавливаемы |
| Отказ | восстановить x/v, вернуть `: → ;`, перейти к следующей записи | вся стабильная конфигурация |
| Копирование | удалить старые v и скопировать целевой код по одной букве через y | программа восстанавливаема |
| Исполнение | прочитать b и D, переписать ячейку, переместить `@`, добавить `_` на границе | остальные ячейки |
| Завершение шага | восстановить y и `:`, вернуть READY перед `^` | исходная программа целиком |

Если вместо очередной записи встретился `#`, подходящей команды нет: управляющая буква идёт влево и выполняется заключительная замена.

### 3.1. Поиск и сравнение без сравнения чисел в Python

Рассмотрим ветвь, где под головкой `0`. Начало кандидата превращается из `;` в `:`. Управляющая буква CMP_0 стоит перед его исходным кодом.

Сопоставление одной пары начинается реальным правилом:

```text
⟨CMP_0⟩u → x⟨TO_STATE_0⟩
```

TO_STATE_0 движется вправо до `#`. CHECK_0 пропускает уже отмеченные v и выполняет:

```text
⟨CHECK_0⟩u → v⟨BACK_0⟩
```

BACK_0 идёт влево до `:`; CMP_0 снова проходит через x и берёт следующую u.

Для кодов `uuu` и `uuu` пары после полных обходов выглядят так:

| Завершённых сопоставлений | Исходный код команды | Текущее состояние |
|---:|---|---|
| 0 | `uuu` | `uuu` |
| 1 | `xuu` | `vuu` |
| 2 | `xxu` | `vvu` |
| 3 | `xxx` | `vvv` |

Это таблица пояснения, а не набор правил с переменными. Каждый обход в исполняемом алгоритме состоит из конечной последовательности буквальных замен.

Нужно различать три отказа:

1. В исходном коде ещё нашлась u, но CHECK дошёл до `[`: код команды длиннее текущего состояния.
2. Исходный код закончился, а CHECK_END после всех v нашёл u: код команды короче текущего состояния.
3. Исходный код закончился на символе чтения, отличном от запомненного 0/1/_: не совпадает символ под головкой.

Во всех случаях FAIL_RIGHT сначала доходит до `[`, затем FAIL_LEFT возвращается к `^`, восстанавливая **и x, и v**. Проход вправо перед восстановлением существенен: при несовпадении символа чтения курсор ещё в программе, а пометки v находятся правее него. Далее FIND_MARK находит единственную `:`, восстанавливает `;`, а SKIP пропускает текущую запись до следующего `;` или `#`.

Успех разрешён только после совпадения символа чтения и достижения `[` в CHECK_END: оба унарных кода исчерпаны полностью.

### 3.2. Копирование целевого состояния

В момент успеха старое состояние полностью состоит из v. Правило

```text
v⟨DELETE_STATE⟩ → ⟨DELETE_STATE⟩
```

удаляет его по одной букве. SEEK_CAND возвращается к `:`, восстанавливая исходный код x → u. SKIP_SOURCE проходит исходный код и символ чтения. COPY оказывается перед кодом целевого состояния.

Каждая его очередная u превращается в y:

```text
⟨COPY⟩u → y⟨COPY_TO_STATE⟩
```

COPY_TO_STATE идёт к `[`. Перед ней срабатывает:

```text
⟨COPY_TO_STATE⟩[ → u⟨COPY_BACK⟩[
```

Так новая u добавляется к текущему состоянию. COPY_BACK возвращается к `:`, SKIP_SOURCE снова находит целевой код, COPY пропускает y. После p обходов целевой код отмечен как y^p, а между `#` и `[` находится u^p. Никакой внешний код не считает p во время симуляции.

### 3.3. Запись и все варианты движения

После целевого кода стоят b и D. Эти два символа выбирают одну из девяти конечных управляющих ветвей WRITE_SEEK_bD. Она доходит до `@`. Направление и записываемый символ хранятся в выборе управляющей буквы, а не в переменной интерпретатора.

Пример записи 1 с движением вправо при исходном 0:

```text
@⟨WRITE_1R⟩0 → 1@⟨EXTEND_R⟩
```

Далее справа либо существует ячейка c, либо находится `]`. Во втором случае применяется конкретное правило:

```text
⟨EXTEND_R⟩] → ⟨CLEAN⟩_]
```

Пример записи 1 с движением влево при исходном 0:

```text
@⟨WRITE_1L⟩0 → ⟨MOVE_L⟩@1
```

Если слева существует `0`, головка переходит на неё:

```text
0⟨MOVE_L⟩@ → ⟨CLEAN⟩@0
```

Если слева сразу `[`, добавляется пустая ячейка:

```text
[⟨MOVE_L⟩@ → [⟨CLEAN⟩@_
```

При S маркер головки сохраняет место. Например:

```text
@⟨WRITE_1S⟩0 → @⟨CLEAN⟩1
```

Все 27 сочетаний b/D/старого символа и все варианты соседей раскрыты в таблице. После движения CLEAN проходит влево, восстанавливает y → u и `: → ;`, затем выполняет:

```text
^⟨CLEAN⟩ → ⟨READY⟩^
```

Это наблюдаемая граница завершённого перехода Тьюринга.

## 4. Полный фиксированный алгоритм и порядок правил

Приоритет — порядок элементов `rules.json`. Нумерация в `rules_readable.txt` начинается с 1. Генератор `fixed_rules.build()` не принимает аргументов, ничего не читает из машины и не импортирует её описание. Все его циклы обходят постоянные конечные наборы из 3 или 18 букв. Функция Q присваивает фиксированным именам последовательные одиночные буквы U+E000…U+E045.

| Номера правил | Назначение |
|---|---|
| 1–19 | достижение и чтение головки |
| 20–40; 178–198; 336–356 | возврат и выбор записи для 0/1/_ |
| 41–105; 199–263; 357–421 | сравнение для 0/1/_ |
| 106–177; 264–335; 422–493 | восстановление и пропуск отклонённой записи |
| 494–555 | удаление старого и копирование нового состояния |
| 556–756 | чтение действия и запись символа |
| 757–764 | движение и расширение ленты |
| 765–782 | восстановление программы и возврат READY |
| 783–800 | остановка при отсутствии перехода |

Последнее правило:

```text
^⟨HALT_BACK⟩ →· !^
```

Оно **единственное заключительное**. Отсутствие команды не заменено эвристикой или лимитом.

Почему не возникает преждевременных замен: левая часть **каждого** правила содержит ровно одну управляющую букву. На корректном достижимом слове она единственна. Для её текущего имени правила либо различают соседний символ слева, либо справа, либо тройку `@ — управление — читаемая ячейка`. Разные варианты несовместимы. Проход исключает свой стоп-символ, для которого существует отдельное правило. Поэтому на каждом нетерминальном достижимом слове применимо ровно одно правило и у него ровно одно вхождение. Стандартный приоритет Маркова и выбор самого левого вхождения соблюдаются без каких-либо исключений.

Генератор не является алгоритмом работы с входной машиной. Он один раз разворачивает сокращённое описание **этой постоянной таблицы**. Можно удалить `fixed_rules.py`, оставить `rules.json`, `engine.py`, `literal_run.py` и закодированный вход — симуляция продолжит работать.

## 5. Реализация и воспроизведение

Требуется Python 3.10 или новее; сторонних пакетов нет. Проверено на Python 3.14. Перед запуском перейдите в каталог проекта. Не используйте `python -O` для проверок: они используют `assert`.

```bash
python3 run.py examples/invert.json 01011 --trace
python3 run.py examples/increment.json 111 --trace
python3 run.py examples/walk.json --trace
python3 run.py examples/immediate.json --trace
python3 run.py examples/long_states.json 0 --trace --budget 2000000
python3 run.py examples/loop_right.json 0110 --budget 20000
python3 verify.py
```

В Windows можно заменить `python3` на `py -3` или `python`, если эта команда запускает подходящую версию.

Полностью отделённый запуск общего механизма замен:

```bash
python3 run.py examples/invert.json 01011 --encode-only > input.word
python3 literal_run.py rules.json input.word
```

Первая команда только кодирует. Вторая ничего не знает о состоянии, головке, программах и переходах. Чтобы исключить проблемы старых оболочек с кодировкой при перенаправлении Unicode, можно сразу использовать готовый файл:

```bash
python3 literal_run.py rules.json examples/invert_01011.word
```

Для буквальной трассировки первых 170 замен:

```bash
python3 run.py examples/invert.json 01011 --trace --micro 170
```

Повторное получение **той же самой** таблицы и примеров:

```bash
python3 fixed_rules.py
python3 examples.py
```

### 5.1. Что именно делает Python

В `Markov.step` цикл просматривает правила в исходном порядке, вызывает `word.find(lhs)` и заменяет найденную буквальную подстроку. Движок не читает `Transition`, не ищет команды M и не содержит операций над головкой или состоянием M. `run.py` не импортирует `reference.py`.

Для ускорения предусмотрен общий фильтр алфавита: правило, содержащее в левой части букву, отсутствующую во всём слове, заведомо неприменимо. Такие правила временно исключаются; относительный порядок остальных сохраняется. Наличие всех букв ещё не считается совпадением: затем всё равно вызывается обычный `str.find` для полной левой части. Фильтр одинаково применим к любой системе буквальных замен, включая правила с пустой левой частью. Он не анализирует формат машины.

`--plain` отключает фильтр. Тогда интерпретатор буквально перебирает все 800 правил при каждой замене. Эквивалентность режимов дополнительно проверена на 400 случайных общих системах замен и на нескольких реальных примерах проекта.

Трассировщик читает конфигурацию только после появления READY. Наблюдатель не возвращает управляющих решений движку. В тестах эталонная машина продвигается на один шаг **после** появления этой границы, и её результат только сравнивается со словом A.

### 5.2. Лимит

`status=terminal` означает заключительную замену. `status=no_rule` — ни одной применимой левой части. Для корректных входов данного симулятора последнее не возникает; оно означает ошибку входа или конструкции.

`status=limit` означает, что внешняя отладочная оболочка исчерпала разрешённое число замен. Это **прерывание проверки**, не остановка машины и не доказательство зацикливания. Сохранённое промежуточное слово можно продолжить тем же движком и той же таблицей. В тестах `transition_limit` аналогично обозначает остановку наблюдения после указанного числа завершённых переходов.

## 7. Доказательство корректности

### 7.1. Обозначения и утверждение

Пусть E(P,q,L,a,R) — стабильное слово `⟨READY⟩^P#u^q[L@aR]`, H(P,q,L,a,R) — такое же слово с `!` вместо READY. Математические переменные в этих обозначениях описывают семейство входных слов, не правил A.

**Теорема.** Для всякой корректно закодированной машины M и её допустимой конфигурации C:

1. Если C имеет следующий переход в C′, то A за конечное положительное число обычных замен переводит E(C) в E(C′), без промежуточной остановки и без промежуточной границы READY.
2. Если в C переход отсутствует, то A за конечное число замен получает H(C), причём последняя замена заключительная.
3. Следовательно, конечные вычисления M и их конечные результаты моделируются правильно, а при бесконечном вычислении M алгоритм A выполняет бесконечно много замен.

В E(C′) представленный участок сохраняется или увеличивается на одну ячейку, согласно соглашению о границах. Абсолютные координаты учитываются отношением представления из §2.2.

### 7.2. Инвариант управления

Изначально управляющая буква одна. В каждой обычной замене ровно одна управляющая буква в левой части заменяется ровно одной в правой. В заключительной — она удаляется. Других источников управляющих букв нет.

Рассмотрим текущую управляющую букву. Полная таблица состоит из следующих типов:

- один вариант для каждого различимого правого соседнего символа;
- один вариант для каждого различимого левого соседнего символа;
- для WRITE — один вариант для каждого символа после `@⟨WRITE⟩`;
- для MOVE_L — различение левого соседа из Γ или `[` при правом `@`.

Проходные правила исключают стоп-символ, пограничное правило его включает. Поэтому два правила одной управляющей буквы одновременно не подходят. Другие управляющие буквы отсутствуют. В достижимых контекстах необходимый сосед существует и входит в перечисленные случаи. Следовательно, применим ровно один вариант, и благодаря единственности управляющей буквы его вхождение тоже единственно.

Это одновременно доказывает корректность приоритетов, соблюдение выбора самого левого вхождения и отсутствие «самопроизвольной» работы других этапов. На некорректные входы лемма не распространяется.

### 7.3. Инвариант чтения и перебора записей

TO_HEAD находит единственный `@`; READ выбирает ветвь с индексом a, равным реально прочитанному символу. До этапа WRITE лента не изменяется, поэтому запомненное a остаётся верным. REWIND доходит до `^`; FIND оказывается перед первой записью или `#`.

Перед каждой новой попыткой сравнения:

- все прежние записи имеют исходный вид;
- текущее состояние равно исходному u^q;
- лента не менялась;
- предыдущие записи уже отвергнуты как не подходящие текущим q и a;
- пометок x/v/y/: нет.

Выбранная `;` становится единственной `:`. Отклонение записи полностью восстанавливает конфигурацию и переводит FIND строго к следующему разделителю, а не к началу той же записи. Число записей конечно.

### 7.4. Лемма сравнения унарных кодов

Пусть исходное состояние кандидата имеет код u^r, а текущее — u^q. После k завершённых парных обходов исходный код имеет вид x^k u^(r−k), текущий — v^k u^(q−k), где 0 ≤ k ≤ min(r,q). Другие записи и лента не изменены.

База k=0 следует из выбора записи. При наличии следующей исходной u она отмечается x. Если CHECK находит следующую текущую u, она отмечается v и происходит возврат к кандидату: инвариант выполнен для k+1. Если вместо неё встретилась `[`, то r>q и кандидат отвергается.

Когда CMP достигает символа чтения, исходные r букв уже отмечены. Если символ не равен a, отказ правилен. Если равен, CHECK_END пропускает все v. Наличие u означает q>r; `[` означает q=r. Следовательно, успех имеет место **ровно при r=q и совпадении символа чтения**.

FAIL_RIGHT доводит курсор до `[`, то есть правее всех x/v. FAIL_LEFT идёт до `^` и меняет все x/v обратно в u. FIND_MARK и SKIP восстанавливают `;` и переходят к следующему кандидату. Поэтому отказ не портит последующие сравнения. Из детерминированности M подходящий кандидат не более чем один; порядок записей не меняет результат.

### 7.5. Лемма копирования

При успехе текущий код целиком состоит из v^q. DELETE_STATE удаляет именно эти буквы до `#`, не затрагивая программу. SEEK_CAND восстанавливает исходные x, затем управление достигает целевого кода u^p.

После j завершённых обходов копирования этот код имеет вид y^j u^(p−j), а поле текущего состояния — u^j. База j=0 — удалённое старое поле. Один обход отмечает очередную u как y и добавляет одну u перед `[`. Обратный проход возвращает управление к тому же целевому коду. Значит, инвариант сохраняется при j+1.

После p обходов следующая буква принадлежит Γ: это записываемый символ b. В поле текущего состояния находится ровно u^p. Исходная длина не угадывается и не вычисляется внешним симулятором.

### 7.6. Лемма записи и движения

DIR читает направление, WRITE_SEEK доходит до единственного `@`. Реальные правила WRITE отдельно покрывают каждую пару b,D и каждый старый символ a.

На уровне представляемой конфигурации они дают следующие исчерпывающие случаи:

| Направление | Условие | Новое представление ленты |
|---|---|---|
| S | любое L,R | `L @ b R` |
| R | R = cR′ | `L b @ c R′` |
| R | R пусто | `L b @ _` |
| L | L = L′c | `L′ @ c b R` |
| L | L пусто | `@ _ b R` |

Это **описание результата доказательства**, а не исполняемые правила с подстроковыми переменными. Каждая строка обеспечена буквальными правилами §3.3 и полной таблицы.

Во всех пяти случаях в старой ячейке записан b, головка имеет правильное положение, прочие существовавшие ячейки не изменены, недостающая ячейка заполнена `_`. В каждом слове остаётся ровно один `@` и непустая лента.

После исполнения все оставшиеся пометки y и `:` находятся в программе, левее головки. CLEAN пересекает их на пути к `^`, восстанавливает исходную программу, а затем создаёт READY. Состояние уже равно p. Получено ровно E(C′), и все стабильные инварианты восстановлены.

### 7.7. Конечность внутренних этапов

Отдельный проход курсора имеет заданный стоп-символ, который существует в нужной стороне по формату соответствующего этапа. На каждой проходной замене расстояние до него уменьшается на 1. Пометки не меняют длину слова. Поэтому каждый такой проход конечен.

Сравнение кандидата делает не более min(r,q)+1 попыток спаривания и одну проверку окончания. В успешной паре число неотмеченных букв исходного кода уменьшается на 1. При несовпадении выполняется конечное восстановление и переход к строго следующей записи. Записей конечное число.

DELETE_STATE уменьшает число v до нуля. Копирование делает ровно p обходов, каждый из которых уменьшает число неотмеченных u **в целевом поле программы**. Добавление u в другом поле не увеличивает этот счётчик. Движение требует конечного числа локальных замен, CLEAN — одного конечного прохода.

Таким образом, один переход M не может потеряться в бесконечном внутреннем цикле A. Эта лемма нужна отдельно от совпадения результатов: одних успешно завершившихся тестов для неё недостаточно.

Грубая оценка также видна из конструкции. Если m — длина программы, n — длина представленного участка, q — длина текущего кода, то один переход или установление отсутствия перехода требует O((m+1)(m+q+n+1)) **замен Маркова**. Сумма длин исходных кодов ограничена m; целевой код при успехе тоже не длиннее m. Это оценка числа абстрактных замен, а не времени Python: поиск буквальной подстроки и построение новой строки имеют дополнительную стоимость. Унарная запись больших номеров заведомо неэкономна.

### 7.8. Остановка и бесконечное вычисление

Если команда отсутствует, каждый кандидат отвергается по лемме сравнения. После последнего кандидата FIND встречает `#`. В этот момент программа, текущее состояние и лента восстановлены; HALT_BACK только проходит к `^`. Единственная заключительная замена даёт H(C). Поэтому отсутствующий переход моделируется корректно, в том числе при пустой программе и немедленной остановке.

Если команда существует, она будет найдена за конечное число попыток и приведёт к E(C′). В ветви успеха HALT_BACK не появляется и заключительное правило не применимо. READY создаётся только после записи, движения и восстановления программы.

Индукцией по числу переходов M получаем соответствие всех конечных префиксов. Если M остановилась после k переходов, A последовательно моделирует их и затем за конечное число замен останавливается на поиске следующей команды.

Если M совершает бесконечно много переходов, для каждого её перехода существует конечный непустой блок обычных замен A с возвратом в READY. Ни один такой блок не заканчивается заключительной заменой или отсутствием правила. Конкатенация бесконечно многих непустых конечных блоков бесконечна. Следовательно, A продолжает работу. Никакое решение общей проблемы остановки в этой конструкции не используется.

### 7.9. Что доказывают и чего не доказывают тесты

Тесты проверяют конкретные исполнения кода: реализацию семантики Маркова, совпадение конфигураций, восстановление программы, крайние случаи и воспроизводимость фиксированной таблицы. Они способны опровергнуть ошибочную реализацию конкретным контрпримером.

Тесты не перебирают бесконечное множество входных машин, всех длин слов или всех вычислений. Универсальность, конечность каждого внутреннего этапа и перенос бесконечного вычисления обосновываются леммами выше. Это математическое доказательство по конструкции; формальной машинной проверки в proof assistant в проекте нет.

### 8.1. Объяснение за одну минуту

«Я построил одну таблицу из 800 правил Маркова. Во входном слове лежит программа машины Тьюринга, её состояние и лента. Состояния кодируются повторениями буквы u, поэтому их количество не ограничено размером алфавита. Служебная буква перемещается по слову обычными заменами. Чтобы найти команду, правила сравнивают унарные коды попарным помечанием, восстанавливают отвергнутые записи, копируют новое состояние, записывают символ и двигают головку. За пределами представленного участка они добавляют пустую ячейку. Если подходящей команды нет, срабатывает заключительное правило. Python лишь выполняет буквальные замены. Отдельный обычный симулятор используется только для проверки».

## Приложение A. Полный генератор фиксированной таблицы

Следующий код — точная копия `fixed_rules.py`. Его `build()` возвращает весь упорядоченный список независимо от входной машины. Тип `Rule` определён в `engine.py` (приложение B). Значения a/b/c/d в циклах — переменные **внешнего конечного развёртывания**, которые исчезают до начала работы Маркова. В JSON остаются исключительно буквальные строки.

```python
"""Строит ОДИН фиксированный конечный нормальный алгоритм Маркова.

Входной машины здесь нет и быть не может: каждое имя вроде ⟨READY⟩ — одна
конкретная буква Юникода, а не переменная. Все циклы ниже идут по постоянным
конечным алфавитам. Авторитетный результат — развёрнутый упорядоченный
список в rules.json.
"""
from pathlib import Path
from collections import Counter
import hashlib
import json
from engine import Rule

TAPE = "01_"
DIRECTIONS = "LRS"
DATA = "^;#u01_LRS[@]xvy:!"


def build():
    controls = {}
    rules = []
    group = ""

    def Q(name):
        if name not in controls:
            controls[name] = chr(0xE000 + len(controls))
        return controls[name]

    def add(lhs, rhs, terminal=False):
        rules.append(Rule(lhs, rhs, terminal, group))

    def right(name, stop):
        # ровно len(DATA) - len(stop) буквальных правил, в порядке алфавита DATA
        for c in DATA:
            if c not in stop:
                add(Q(name) + c, c + Q(name))

    def left(name, stop, restore=None):
        restore = {} if restore is None else restore
        for c in DATA:
            if c not in stop:
                add(c + Q(name), Q(name) + restore.get(c, c))

    group = "01 read scanned symbol"
    add(Q("READY") + "^", "^" + Q("TO_HEAD"))
    right("TO_HEAD", "@")
    add(Q("TO_HEAD") + "@", "@" + Q("READ"))

    # три ветви помнят только прочитанный символ (0, 1 или _) — и всё
    for a in TAPE:
        name = lambda stem: stem + "_" + a
        group = "02 rewind and choose record " + a
        add(Q("READ") + a, Q(name("REWIND")) + a)
        left(name("REWIND"), "^")
        add("^" + Q(name("REWIND")), "^" + Q(name("FIND")))
        add(Q(name("FIND")) + ";", ":" + Q(name("CMP")))
        add(Q(name("FIND")) + "#", Q("HALT_BACK") + "#")

        group = "03 compare unary source " + a
        add(Q(name("CMP")) + "x", "x" + Q(name("CMP")))
        add(Q(name("CMP")) + "u", "x" + Q(name("TO_STATE")))
        right(name("TO_STATE"), "#")
        add(Q(name("TO_STATE")) + "#", "#" + Q(name("CHECK")))
        add(Q(name("CHECK")) + "v", "v" + Q(name("CHECK")))
        add(Q(name("CHECK")) + "u", "v" + Q(name("BACK")))
        add(Q(name("CHECK")) + "[", Q(name("FAIL_RIGHT")) + "[")
        left(name("BACK"), ":")
        add(":" + Q(name("BACK")), ":" + Q(name("CMP")))
        for b in TAPE:
            target = "END_TO_STATE" if a == b else "FAIL_RIGHT"
            add(Q(name("CMP")) + b, Q(name(target)) + b)
        right(name("END_TO_STATE"), "#")
        add(Q(name("END_TO_STATE")) + "#", "#" + Q(name("CHECK_END")))
        add(Q(name("CHECK_END")) + "v", "v" + Q(name("CHECK_END")))
        add(Q(name("CHECK_END")) + "u", Q(name("FAIL_RIGHT")) + "u")
        add(Q(name("CHECK_END")) + "[", Q("DELETE_STATE") + "[")

        group = "04 reject restore and skip " + a
        right(name("FAIL_RIGHT"), "[")
        add(Q(name("FAIL_RIGHT")) + "[", Q(name("FAIL_LEFT")) + "[")
        left(name("FAIL_LEFT"), "^", {"x": "u", "v": "u"})
        add("^" + Q(name("FAIL_LEFT")), "^" + Q(name("FIND_MARK")))
        right(name("FIND_MARK"), ":")
        add(Q(name("FIND_MARK")) + ":", ";" + Q(name("SKIP")))
        right(name("SKIP"), ";#")
        for end in ";#":
            add(Q(name("SKIP")) + end, Q(name("FIND")) + end)

    group = "05 erase old state and copy target"
    add("v" + Q("DELETE_STATE"), Q("DELETE_STATE"))
    add("#" + Q("DELETE_STATE"), Q("SEEK_CAND") + "#")
    left("SEEK_CAND", ":", {"x": "u"})
    add(":" + Q("SEEK_CAND"), ":" + Q("SKIP_SOURCE"))
    add(Q("SKIP_SOURCE") + "u", "u" + Q("SKIP_SOURCE"))
    for a in TAPE:
        add(Q("SKIP_SOURCE") + a, a + Q("COPY"))
    add(Q("COPY") + "y", "y" + Q("COPY"))
    add(Q("COPY") + "u", "y" + Q("COPY_TO_STATE"))
    right("COPY_TO_STATE", "[")
    add(Q("COPY_TO_STATE") + "[", "u" + Q("COPY_BACK") + "[")
    left("COPY_BACK", ":")
    add(":" + Q("COPY_BACK"), ":" + Q("SKIP_SOURCE"))

    group = "06 read action and write scanned cell"
    for b in TAPE:
        add(Q("COPY") + b, b + Q("DIR_" + b))
        for d in DIRECTIONS:
            seek = "WRITE_SEEK_" + b + d
            write = "WRITE_" + b + d
            add(Q("DIR_" + b) + d, d + Q(seek))
            right(seek, "@")
            add(Q(seek) + "@", "@" + Q(write))
            for old in TAPE:
                if d == "R":
                    replacement = b + "@" + Q("EXTEND_R")
                elif d == "L":
                    replacement = Q("MOVE_L") + "@" + b
                else:
                    replacement = "@" + Q("CLEAN") + b
                add("@" + Q(write) + old, replacement)

    group = "07 move head and extend tape"
    for c in TAPE:
        add(Q("EXTEND_R") + c, Q("CLEAN") + c)
    add(Q("EXTEND_R") + "]", Q("CLEAN") + "_]")
    for c in TAPE:
        add(c + Q("MOVE_L") + "@", Q("CLEAN") + "@" + c)
    add("[" + Q("MOVE_L") + "@", "[" + Q("CLEAN") + "@_")

    group = "08 restore program and finish transition"
    left("CLEAN", "^", {"y": "u", ":": ";"})
    add("^" + Q("CLEAN"), Q("READY") + "^")

    group = "09 terminate on missing transition"
    left("HALT_BACK", "^")
    add("^" + Q("HALT_BACK"), "!^", terminal=True)

    # статические проверки самой таблицы; к входной машине отношения не имеют
    symbols = set(controls.values())
    assert len(DATA) == len(set(DATA))
    assert not symbols.intersection(DATA)
    assert len({r.lhs for r in rules}) == len(rules)
    assert sum(r.terminal for r in rules) == 1
    for r in rules:
        assert r.lhs and sum(c in symbols for c in r.lhs) == 1
        assert sum(c in symbols for c in r.rhs) == (0 if r.terminal else 1)
        assert set(r.lhs + r.rhs) <= set(DATA) | symbols
    assert {c for r in rules for c in r.lhs if c in symbols} == symbols
    return tuple(rules), controls


def export(directory):
    rules, controls = build()
    directory = Path(directory)
    blob = json.dumps([r.__dict__ for r in rules], ensure_ascii=True, indent=2) + "\n"
    (directory / "rules.json").write_text(blob, encoding="utf-8")
    (directory / "controls.json").write_text(
        json.dumps(controls, ensure_ascii=True, indent=2) + "\n", encoding="utf-8")
    alias = {v: "⟨" + k + "⟩" for k, v in controls.items()}
    show = lambda s: "".join(alias.get(c, c) for c in s)
    lines = ["Каждое ⟨ИМЯ⟩ обозначает ОДНУ букву. Порядок строк — приоритет.",
             "→· — заключительная замена. Исполняемые строки — в rules.json.", ""]
    previous = None
    for i, rule in enumerate(rules, 1):
        if rule.group != previous:
            lines.append("\n# " + rule.group)
            previous = rule.group
        lines.append(f"{i:04d}  {show(rule.lhs)} {'→·' if rule.terminal else '→'} {show(rule.rhs)}")
    (directory / "rules_readable.txt").write_text("\n".join(lines) + "\n", encoding="utf-8")
    info = {
        "rules": len(rules), "control_letters": len(controls),
        "data_letters": len(DATA), "alphabet_size": len(DATA) + len(controls),
        "terminal_rules": sum(r.terminal for r in rules),
        "rules_json_sha256": hashlib.sha256(blob.encode()).hexdigest(),
        "groups": dict(Counter(r.group for r in rules)),
        "data_alphabet": DATA,
    }
    (directory / "rules_info.json").write_text(json.dumps(info, indent=2) + "\n")
    return info


if __name__ == "__main__":
    print(json.dumps(export(Path(__file__).parent), indent=2))
```

## Приложение B. Полный общий интерпретатор

Точная копия `engine.py`. Обратите внимание на отсутствие кодировки машины, таблицы её переходов и операций над головкой.

```python
"""Общий буквальный интерпретатор нормальных алгоритмов Маркова.

Про машины Тьюринга здесь ничего не известно: только список правил и слово.
"""
from dataclasses import dataclass
from functools import lru_cache
import json


@dataclass(frozen=True)
class Rule:
    lhs: str
    rhs: str
    terminal: bool = False
    group: str = ""


@dataclass(frozen=True)
class Replacement:
    word: str
    rule_index: int                 # с нуля
    position: int
    terminal: bool


@dataclass(frozen=True)
class RunResult:
    word: str
    replacements: int
    status: str                     # terminal / no_rule / limit


def load_rules(path):
    return tuple(Rule(**item) for item in json.loads(path.read_text(encoding="utf-8")))


class Markov:
    def __init__(self, rules, *, alphabet_filter=True):
        self.rules = tuple(rules)
        self.alphabet_filter = alphabet_filter
        self._required = tuple(frozenset(r.lhs) for r in self.rules)
        # фильтр выкидывает только правила с буквами, которых во всём слове нет;
        # порядок правил и поиск вхождения он не меняет
        self._candidates = lru_cache(maxsize=2048)(self._filter)

    def _filter(self, present):
        return tuple(i for i, needed in enumerate(self._required) if needed <= present)

    def step(self, word):
        indices = (self._candidates(frozenset(word)) if self.alphabet_filter
                   else range(len(self.rules)))
        for i in indices:            # приоритет — исходный порядок правил
            rule = self.rules[i]
            pos = word.find(rule.lhs)  # самое левое вхождение; для "" будет 0
            if pos != -1:
                changed = word[:pos] + rule.rhs + word[pos + len(rule.lhs):]
                return Replacement(changed, i, pos, rule.terminal)
        return None

    def run(self, word, max_replacements=1000000, observer=None):
        if max_replacements < 0:
            raise ValueError("max_replacements должен быть неотрицательным")
        for count in range(1, max_replacements + 1):
            applied = self.step(word)
            if applied is None:
                return RunResult(word, count - 1, "no_rule")
            word = applied.word
            if observer is not None:
                observer(count, applied)  # наблюдатель только смотрит; его ответ не используется
            if applied.terminal:
                return RunResult(word, count, "terminal")
        # limit ничего не говорит об остановке в принципе — просто кончился бюджет
        return RunResult(word, max_replacements, "limit")
```
